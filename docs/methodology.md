# 方法与质量边界

1. **采集**：汽车之家车系列表接口返回 `Koubeiid` 和 `showId`；详情页 URL 使用 `showId`，不能把 `Koubeiid` 拼进 URL。增量扫描按已知评论页停止，不宣称完整历史覆盖。
2. **清洗**：列表正文去 HTML、保留原始 JSON；按需从详情页提取「最满意/最不满意/智能化」等分项。详情抓取失败不得丢失列表正文或旧详情。
3. **候选召回**：逐句执行座舱主题规则，按来源评论键去重。正面与负面规则是保守候选，并非精确情感模型；一条评论可涉及多个主题。
4. **日报去重**：评论层以 `(source, source_review_id, series_id)` 唯一，反馈层以评论、主题、句子指纹唯一；`reported_findings` 记录已写入报告的句子。首轮先生成历史基线，之后日报只报告新增候选。
5. **人工验收**：发布前复核原文与链接、车型/年款/软件版本、是否亲历、是否旧版本问题、是否跨句误判。优先报告具体的「操作—实际结果—期望」，不从单条评论推断发生率。

当前不做跨评论语义聚类和人工问题状态管理；不同评论对同一问题的陈述会合并在同一主题下，但不会自动判定为同一个缺陷。公开前可增加人工审核台账、主题 ID 和复现状态。
